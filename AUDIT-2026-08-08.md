## High

### H1 — Three dead links, including the entry the list's own narrative is built around

All 27 URLs were checked with `curl -sSL`.

| Line | URL | Status |
| :--- | :--- | :--- |
| `README.md:41` | `github.com/janakhpon/mon_OCR` | **404** |
| `README.md:68` | `github.com/janakhpon/mon-corpus-scraper` | **404** |
| `README.md:28` | Play Store `dev.janakhpon.monocr` | **404** |

**Reasoning.** `mon_OCR` is load-bearing: it is the only item under "Training & Research" and the
first link in the pipeline sentence at `:24` — *"mon_OCR trains the model, monocrhf distributes the
weights, monocr-onnx and monocr run inference."* `mon-corpus-scraper` is the only item under "Data
Collection Tools", so that section is empty in practice, and `:56` cross-references it as the way to
harvest monnews.

Both repositories 404 under the `MonDevHub` org as well, so they are private or deleted rather than
relocated. The Play Store 404 persists with region parameters, so it is not a regional block.

`README.md:28` also asserts *"an iOS build is in App Store review"* — unverifiable and inherently
stale-prone.

**Impact.** `CONTRIBUTING.md:11` sets the bar these entries fail: *"**Available** — the link works
and the resource is publicly accessible."* The list currently violates its own inclusion rule, and a
visitor to the default branch sees three broken links.

**Fix.** Re-open the repositories, or remove the entries per the repo's own contributing rule.

## Medium

### M1 — The declared quality gate fails on a repository setting, not on the content

`CONTRIBUTING.md:38-42` and `.github/PULL_REQUEST_TEMPLATE.md:14` both require `npx awesome-lint`.
Running it:

```
✖  1:1  The repository should have "awesome" as a GitHub topic       remark-lint:awesome-github
✖  1:1  The repository should have "awesome-list" as a GitHub topic  remark-lint:awesome-github
2 errors
```

Not a rate-limit artifact — the GitHub API confirms the repository has no topics. Every other
awesome-lint rule passes. Re-run 2026-08-12: same two errors, exit code 1, nothing else reported.

**Impact.** Every contributor following the documented process hits two failures caused by repository
settings they cannot change. The missing topics also keep the list out of GitHub's `awesome-list`
topic discovery, which is most of the point of being an awesome list.

**Fix.** The maintainer adds the topics `awesome` and `awesome-list` in repository settings on GitHub.
No code, no file, nothing a pull request can carry. Treat this as an admin click that is still
outstanding, not as work waiting on an engineer.

## What is good, specifically

- **24 of 27 links are live, and every non-GitHub link resolves.** That includes the ones most prone
  to rot: `fliphtml5.com`, `iso639-3.sil.org`, `unicode.org`, `monbuddhistfoundation.co.uk`,
  `mnw.wikipedia.org`.
- **The technical claims are accurate to their sources.** Checked against the HuggingFace model card:
  CER 0.025, WER 0.211, "roughly 3M samples" against a stated 3,030,000, and "315-character charset"
  against the card's "Vocabulary: 315 characters". Numeric claims in curated lists are usually
  drifted or invented. These are not.
- **Governance is complete and proportionate**: LICENSE, a CODE_OF_CONDUCT with a working reporting
  route rather than a placeholder address, a CONTRIBUTING with an explicit inclusion bar, and a PR
  checklist. More discipline than most six-file lists carry, and none of it is bloat.
- **The list is honest about its own gaps** — `README.md:52`: *"Open Mon corpora are scarce; if you
  maintain or know of one, please see Contributing."*
- **Every entry follows the declared format**, all Contents anchors resolve, and no duplicates exist.
  `monocr-onnx` and `monocr` look like duplicates but are genuinely distinct.
